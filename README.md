# 胶片放行台

一个纯前端本地应用，把纸质胶片的「核对台」补成「放行台」：外检回执按片段编号归并、待裁定不能生成许可、许可绑定顺序与风险结论并在变化时立即作废、按每盘 150 秒重新排盘、两窗口并发保存做版本控制、保存失败留下批次可重试。

## 结构

- `index.html` — 页面骨架与标签页。
- `styles.css` — 样式。
- `js/rules.js` — 规则判定层：回执解析与归并、待裁定、排盘、许可绑定/作废、装盘作废、字段级冲突检测。
- `js/storage.js` — 持久化层：localStorage 读写、版本号乐观并发、未完成批次落盘与重试。
- `js/ui.js` — 页面渲染层：片段 / 回执 / 装盘 / 许可 / 批次五个页面。
- `app.js` — 主控制器：持有内存状态、串联三层、响应操作。

规则判定、持久化、页面拆分维护，互不耦合。

## 直接使用

直接打开 `index.html` 即可，也可以在本目录启动静态服务访问。

## 典型流程

1. **片段页**录入片段，排片员可直接改时长、颜色、破损，可拖拽排序。
2. **回执页**粘贴纸质外检回单，按片段编号归并。同一片段两种结论都保留并标「待裁定」，不会盖掉排片员刚改的内容；裁定前不能生成放映许可。
3. **装盘页**按每盘 150 秒重新排盘。顺序、时长、颜色偏移或破损任一变化，装盘方案立即作废。
4. **许可页**生成放映许可，许可绑定当时的片段顺序、风险结论和盘数；信息变化时许可立即作废。
5. **批次页**处理并发与失败：
   - 两个窗口同时保存时，版本落后的那次不覆盖新数据，冲突字段逐行列出等人工确认，可「按选择合并并保存」「整体保留本地」「整体采用远程」。
   - 保存失败会留下未完成批次，可重试。勾选「模拟下次保存失败」可演示该流程。
