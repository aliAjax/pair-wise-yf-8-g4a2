# 胶片分镜条放行台

在原"核对台"基础上补成的纯前端本地放行台：整理纸质放映胶片片段、拖拽排序、登记晚到的纸质外检回执、对双结论做人工裁定、按每盘 150 秒排盘并签发放映许可，同时处理两个窗口并发保存冲突与失败重试。

直接打开 `index.html` 即可使用（或在本目录起静态服务）。首次打开会自动迁移旧版核对台的本地数据。

## 业务规则

- **外检回执按片段编号归并**：纸质回单晚到只新增"外检结论"，绝不覆盖排片员刚改的时长、颜色和破损。同一编号两种结论不一致时标为**待裁定**，两种结论都保留；裁定前不能生成放映许可。
- **排片员再改风险字段**：改时长 / 颜色 / 破损会与外检结论重新比对（改一致即一致，改出差异重新待裁定，旧裁定失效）。
- **放映许可绑定指纹**：签发时的片段顺序、各片段风险结论（时长/颜色/破损）和装盘盘数。任一项变化，许可立即作废、装盘方案立即按每盘 150 秒重排。
- 已签发许可下晚到不一致回执：许可变"暂缓放行"（指纹未破但存在待裁定），裁定采自检后恢复有效，采外检导致指纹变化则作废。
- **装盘**：按当前顺序贪心装，每盘 ≤ 150 秒；单片超时独占一盘并标"单片超时"。
- **并发保存**：数据带版本号，落后版本保存不会覆盖新数据；弹窗按"双方都改 / 仅本窗口 / 仅另一窗口"列出冲突字段，人工勾选确认后才能强制覆盖，也可直接采用新版本。
- **保存失败**：只产生未完成批次（完整数据+祖先版本+祖先快照），已落盘数据不动；批次可单个/全部重试，重试撞新版本同样走冲突确认。

## 结构（规则判定、持久化、页面拆分维护）

- `js/rules.js` — 规则判定层，纯函数、无 DOM / localStorage 依赖，UMD 同时可在 Node 引用。
- `js/storage.js` — 持久化层：版本化记录、乐观锁提交、未完成批次、跨窗口 storage 广播、可注入内存后端与失败模拟。
- `js/views/` — 页面层：`desk.js`（排片核对）、`receipts.js`（外检回执与裁定）、`release.js`（签放与装盘）、`ui.js`（公共工具）。
- `js/app.js` — 编排层：工作区状态、保存/冲突/重试、跨窗口跟进、页面切换。
- `test/` — 规则层与持久化层的 Node 测试。

## 测试

```bash
node --test test/
```

页面上的"故障演练（下次保存失败）"开关用于手动验证未完成批次与重试；并开两个浏览器窗口可验证并发保存冲突弹窗。
